## 1. 목적

문서 등록을 "파일 먼저"로 바꿔 입력을 줄이고, 업로드 진행·실패·재시도를 분명히 보여 준다. 로그인·가입 화면을 승인된 시안의 2단 구성으로 바꾼다. 검증 규칙·API·권한은 바꾸지 않는다.

## 2. 범위

- In
  - 문서 등록: 파일 선택(끌어다 놓기) → 제목(파일 이름으로 자동 채움) → 선택 입력(설명·초기 버전 내용, 접힘).
  - 업로드 진행률(전송 %·서버 확인 중), 실패 시 입력 유지 + "다시 시도", 중복 제출 방지(기존 유지).
  - 새 버전 업로드 모달에도 같은 진행률·다시 시도.
  - 공통 API 클라이언트: `onUploadProgress` 옵션(XHR). 헤더·쿠키·CSRF 재시도·오류 변환은 fetch 경로와 같다.
  - 로그인·가입: 데스크톱 2단(서비스 소개 | 폼), 모바일 1단. 비밀번호 표시/숨기기(기존 `PasswordInput`) 유지.
- Out
  - 프로젝트 목록·생성·초대 관리 화면 구조 변경(이미 디자인 토큰을 쓰고 있어 그대로 둔다), 업로드 취소, 이어 올리기.

## 3. 동작

### 3.1 제목 자동 채움

1. 제목 출처를 `auto`(파일 이름) / `user`(직접 입력) / `empty`로 둔다.
2. 파일을 고르면 출처가 `user`가 아닐 때만 제목을 "확장자를 뺀 파일 이름"(밑줄은 공백, 200자까지)으로 바꾼다.
3. 파일을 빼면 `auto` 제목은 비운다. 직접 입력한 제목은 파일을 바꾸거나 빼도 유지한다.
4. 직접 입력란을 모두 지우면 출처가 `empty`가 되어 다음 파일 이름으로 다시 채운다.

### 3.2 선택 입력

- 기본으로 접혀 있다. 접힌 상태에서 값이 있으면 "입력됨"을 표시한다.
- 설명·초기 버전 내용에 클라이언트·서버 검증 오류가 있으면 자동으로 펼친다.

### 3.3 업로드

- 전송 중: 진행 막대(`role=progressbar`, `aria-valuenow`)와 "파일을 업로드하는 중입니다. N%". 100%가 되면 "서버에서 파일을 확인하는 중입니다".
- 브라우저가 진행률을 주지 않으면 진행률 없는 막대와 문구만 보인다.
- 실패: 입력을 유지하고 오류 상자에 "다시 시도"(같은 폼 제출). 네트워크 오류는 자동으로 다시 보내지 않는다(결과 불명확, 기존 SPEC-04 원칙).
