# DocFlow UI/UX 2.0 — 디자인 프로토타입 (Phase 1, Issue #67)

서비스 코드와 분리된 **정적 고충실도 프로토타입**이다. 목업 데이터만 사용하며 실제 API·DB·AI를 호출하지 않는다.
디자인 승인 전까지 `frontend/`·`backend/` 코드는 변경하지 않는다.

## 1. 보는 방법

- 빌드·설치 없음, 외부 CDN 없음. `design/ui-ux-2/prototype/index.html`을 브라우저로 직접 연다.
  - 또는 `npx serve design/ui-ux-2/prototype` 후 표시된 주소로 접속한다.
- 해시 라우트

| 화면 | 경로 |
| --- | --- |
| 로그인 / 회원가입 | `#/login`, `#/signup` |
| 홈 | `#/` |
| 프로젝트 목록 / 상세 | `#/projects`, `#/projects/2?tab=docs\|members\|activity\|settings` |
| 문서 등록 | `#/projects/2/new` |
| 문서 상세(3단) | `#/doc/2?v=3`, 확정 문서 `#/doc/3`, Office 문서 `#/doc/4` |
| 버전 비교 | `#/compare/2?mode=pdf&base=2&target=3`, `mode=text` |
| 초대 관리 | `#/invites` |

- 오른쪽 아래 **Prototype** 패널에서 상태를 바꾼다: 역할(오너/구성원), AI(켜짐/꺼짐), 피드백(있음/없음), 상태(정상/로딩/오류).
  - 같은 값을 쿼리로도 줄 수 있다: `?role=member&ai=off&fb=none&st=loading`. `shot=1`이면 패널을 숨긴다.
- 단축키(비교 화면): `j`/`k` 다음·이전 변경.

## 3. 디자인 결정

- **스타일**: Linear·Figma 계열. 장식보다 정보 밀도와 정렬. 카드 중첩을 줄이고 1px 구분선과 표 중심으로 구성했다.
- **색**: 기존 브랜드 블루 `#2563eb` 유지, Slate 중립색. 보조 텍스트 `#64748b`(흰 배경 4.76:1, AA). `#94a3b8`은 장식에만 쓴다.
  - 상태: 협업 중 = 파랑 원형 점, 최종 확정 = 초록 **사각** 점(색 외에 모양으로도 구분).
  - 변경: 추가 = 초록 실선, 삭제 = 빨강 점선, 수정 = 주황 점묘선(색각 이상 대응).
- **셸**: 기본 240px 사이드바. 문서 상세는 56px 레일, 비교는 사이드바 없는 집중 모드로 작업 영역을 넓힌다.
- **문서 상세 3단**: `버전 260px | 뷰어 | 협업 360px`. 버전 패널은 44px로 접힌다.
  - 오른쪽 탭: 피드백(기본) / AI 요약(AI 꺼지면 탭 자체를 숨김) / 정보 / 활동. 입력창은 하단 고정.
  - 헤더 액션은 역할·상태에 따라 바뀐다: 오너+협업 중 → 버전 비교·최종본 확정·새 버전, 확정 → 버전 비교·최종본 받기.
- **최종본 확정**: 버전을 직접 고르는 라디오, 최신이 아닌 버전 경고, "되돌릴 수 없음" 안내, 확인 체크박스를 모두 통과해야 버튼이 활성화된다.
- **비교**: 버전 선택·교체·모드(PDF/텍스트)·변경 수·이전/다음을 상단 한 줄에 둔다. 툴바에 확대·폭 맞춤·회전·동기 스크롤·강조 표시·범례.
  - 분할선 드래그로 좌우 비율을 바꾸고, 변경 패널(300px)은 접을 수 있다. 패널 항목 클릭 시 해당 위치로 이동하고 링으로 표시한다.
- **상태 화면**: 로딩(스켈레톤), 오류(재시도), 빈 상태(첫 행동 버튼), Office 미리보기 미지원(원본 받기)을 모두 정의했다.
- **모바일(≤760px)**: 사이드바를 숨기고 상단 바로 전환. 3단 화면은 탭으로 한 패널씩 보여 준다.
- **글꼴**: 시스템 글꼴 스택(Pretendard 우선 지정). 구현 시 자체 호스팅 여부는 §6에서 결정.

## 5. 현재 UI 대비 개선

1. 문서 상세: 카드가 세로로 쌓여 스크롤해야 보이던 버전·피드백을 뷰어 옆에 두어 **한 화면에서 보면서 피드백**한다.
2. 미리보기: 브라우저 내장 iframe 대신 PDF.js 뷰어로 확대·폭 맞춤·회전·페이지 이동을 통일한다.
3. 비교: 변경 위치로 바로 이동(패널·`j`/`k`), 동기 스크롤, 텍스트·PDF 전환을 한 화면에서 한다.
4. 최종본 확정: 확정할 버전을 명시적으로 고르고, 최신이 아닌 버전 확정과 되돌릴 수 없음을 경고한다.
5. 확정 문서: 상단 배너로 읽기 전용임과 "최신 버전 ≠ 최종본" 여부를 항상 알린다.
6. 문서 목록: 상태·최신·최종본 열과 필터·정렬로 상태를 바로 파악한다.
7. 상태 표현: 색에만 의존하지 않고 모양·선 종류로 구분한다(접근성).
8. 모바일: 3단 화면과 비교 화면을 탭 방식으로 사용할 수 있다.

## 6. 기술 제약과 API 필요 사항 (Phase 2에서 SPEC으로 확정)

| 항목 | 현재 | 필요 | DB 변경 |
| --- | --- | --- | --- |
| 홈 지표·최근 문서 | 홈은 `/api/projects`, `/api/activities`만 조회. `ProjectSummary`에 문서 수 없음 | 접근 가능한 프로젝트 전체의 최근 문서·상태별 개수를 주는 **읽기 전용 API 1개** | 없음 |
| 문서 목록 "업데이트" 열 | `DocumentSummary`에 `updatedAt`·최근 업로더·파일 형식 없음(`finalVersionNumber`는 있음) | 응답 필드 추가(`updatedAt`, `latestUploader`, `contentType`) | 없음(기존 컬럼에서 조회) |
| 버전 목록의 피드백 수 | 버전별 피드백 수 없음 | 버전 목록 응답에 `feedbackCount` 추가 또는 Frontend 집계 | 없음 |
| 문서 상세 미리보기 | iframe(Blob URL) | 비교 화면의 PDF.js(`pdfjs-dist` 6.5.438, 이미 도입)를 공용 뷰어로 분리. 실패 시 iframe 대체 | 없음 |
| 글꼴 | 시스템 글꼴 | Pretendard(OFL) 서브셋 woff2를 `next/font/local`로 자체 호스팅 — **새 자산이므로 별도 승인 필요**. 미승인 시 시스템 글꼴 유지 | 없음 |
| AI 요약 탭 | 기존 API(SPEC-12/13) 사용 | 추가 없음. 운영 AI는 현재 비활성 | 없음 |

- 권한·상태 전이 검증은 계속 Backend가 수행한다. 화면의 버튼 숨김은 보조 수단이다.
- 새 npm 의존성은 계획하지 않는다(Tailwind 4로 토큰·컴포넌트 구현).
