# ADR-0011: PDF 변경 하이라이트 — PDF.js(pdfjs-dist) 렌더링

- 상태: 승인 (2026-11-24 사용자 승인: "PDF.js 도입을 승인")
- Issue: #56 (SPEC-13)

## 결정

1. `pdfjs-dist@6.5.438`(Apache-2.0, 2026-11-01 공개)을 Frontend 의존성으로 정확한 버전으로 고정한다. Node 엔진 요구 `>=22.13`(프로젝트 Node 22와 호환). 선택 의존성 `@napi-rs/canvas`(Node 전용)는 브라우저에서 쓰지 않는다.
2. 비교 화면의 PDF 보기에서만 동적 import한다. 문서 상세의 기존 미리보기(브라우저 기본 PDF 뷰어 iframe)는 바꾸지 않는다.
3. 원본 PDF는 기존 권한 확인 다운로드 API로 받아 메모리에서 연다.
4. 좌표는 SPEC-10의 회전 전 사용자 공간 값을 PDF.js 뷰포트로 변환한다(회전·확대는 뷰포트가 처리).

## 고려한 대안

| 대안 | 채택하지 않은 이유 |
| --- | --- |
| 기존 iframe 위에 겹쳐 그리기 | 브라우저 내장 뷰어의 확대·스크롤 상태를 알 수 없어 좌표를 맞출 수 없음 |
| 서버에서 강조를 그린 이미지·PDF 생성 | 서버 렌더링 부하·저장 공간, 확대 시 화질 저하 |
| react-pdf 등 래퍼 | 추가 의존성. 필요한 기능(페이지 그리기·뷰포트 변환)은 pdfjs-dist만으로 충분 |
| 문서 상세 미리보기도 PDF.js로 교체 | 요청 범위(변경 위치 확인)를 넘는 변경이며 기존 동작(다운로드 대체 안내 등) 회귀 위험 |

## 영향

- Frontend 번들: PDF.js는 비교 화면에서 PDF 보기를 열 때만 내려받는다.
- 보안: 신뢰할 수 없는 PDF를 브라우저 작업자에서 해석한다. 원본은 같은 출처 API로만 받으며 다른 사이트에서 불러오지 않는다. PDF.js 보안 업데이트를 따른다.
