## 5. Before / After (같은 데이터·같은 해상도, `scripts/capture.js`)

측정 정의: 페이지 높이 = 문서 스크롤 높이(After의 작업 공간은 페이지가 스크롤하지 않고 패널 안에서 스크롤한다). PDF 표시 영역 = 화면(뷰포트) 안에 보이는 문서 표시 영역 중 가장 큰 것의 면적 비율. 클릭 수 = 화면 진입 후 PDF가 보일 때까지 필요한 클릭.

| 지표 | Before | After |
| --- | --- | --- |
| 문서 상세: PDF가 보일 때까지 클릭 | 1 ("미리보기 열기") | 0 |
| 문서 상세 1440×900: 페이지 높이 | 2,458px (2.7화면, 미리보기 연 뒤) | 900px (1화면, 패널별 스크롤) |
| 문서 상세 1440×900: PDF 표시 영역 | 17.8% | 45.6% |
| 문서 상세 1920×1080: PDF 표시 영역 / 페이지 높이 | 18.8% / 2.4화면 | 57.6% / 1화면 |
| 문서 상세 1280×720: PDF 표시 영역 / 페이지 높이 | 9.5% / 3.2화면 | 38.9% / 1화면 |
| 문서 상세 1440×900: 첫 화면에 PDF와 피드백 입력란이 함께 보이는가 | 아니오(스크린샷 `before/05`: 오른쪽 열을 버전 목록이 채우고 피드백 카드는 그 아래, 페이지 스크롤 필요) | 예(`after/05`: 가운데 뷰어 + 오른쪽 피드백, 입력창 하단 고정) |
| 확정 문서 1440×900: PDF 표시 영역 | 0% (미리보기 닫힘) | 43.4% |
| 버전 비교: PDF가 보일 때까지 클릭 | 1 ("PDF에서 보기") | 0 (PDF 기본) |
| 버전 비교 1440×900: 한 열의 PDF 표시 영역 / 페이지 높이 | 10.0% / 1.5화면 | 30.9% / 1화면 |
| 모바일 390: 문서 상세 페이지 높이 / PDF 영역 | 3,297px(3.9화면) / 0% | 844px(1화면) / 76.4% |
| 모바일 390: 비교 페이지 높이 | 2,387px(2.8화면) | 844px(1화면) |
| 홈 1440×900: 페이지 높이 | 1,382px | 900px |

주의
- Before의 문서 상세 미리보기는 브라우저 내장 PDF 뷰어(iframe)다. 헤드리스 Chromium은 내장 뷰어를 그리지 않아 Before 스크린샷의 iframe 안은 비어 있다. 면적은 iframe 상자 기준으로 측정했다.
- 사용자 만족도·성능 수치는 측정하지 않았다.

## 7. 남은 위험과 미검증

- Windows 실제 브라우저(Chrome·Edge)와 실제 모바일 기기 확인: 미검증(사용자).
- 실제 Claude API 응답으로 AI 요약·변경 요약 표시: 미검증(유료 호출 미승인). 화면 상태는 Stub으로 확인.
- Office 변환을 켠 환경에서 변환본 PDF.js 표시: 로컬 단위 수준만 확인(운영은 변환 꺼짐).
- 큰 파일(수 MB) 업로드 진행률 표시: 단위 테스트로만 확인(검증 데이터 파일이 20KB 수준이라 진행 막대가 순간적으로 지나감).
- 300쪽 근처 긴 PDF의 메모리 사용량: 측정하지 않음(멀리 있는 페이지 캔버스 해제는 구현·코드 검토만).
- 운영 배포·운영 DB: 하지 않음(미승인).

## 8. 재현 방법

`design/ui-ux-2/verification/scripts/`: `make_pdfs.py`(검증 PDF 생성, reportlab·한글 글꼴) → Backend(local 프로파일, `DEV_SEED_PASSWORD` 지정) → `node seed.mjs > seed.json` → Frontend standalone 실행 → `node capture.js <out> after` / `node verify.js <out>`. 스크립트는 로컬 검증 DB 전용이며 운영 환경에 쓰지 않는다.
